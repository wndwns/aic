1问题与目标

青藏高原牧区的主要致灾气象事件是雪灾、寒潮、强降雨与干旱。这些事件在空间上连片发生 （雪云过境、草场连片受灾），在时间上具有持续性（连续降雪累积）。 而现有做法把 26 个县当作彼此独立的行、把月份当作彼此独立的样本， 这丢掉了本问题最本质的两个结构：空间扩散与时间记忆。

本文要回答三个问题：

  1. 把「县」连成图、把「月」连成序列，能不能比逐行独立的树模型更好？
  2. 把气象物理规律写进损失函数（PINN），在样本极少的情况下是不是真的有用？
  3. 能不能做提前预测（这才叫预警），而不是同期识别？

2.2 单位一律取接口自报值

所有单位以 API 响应中的 daily_units 为唯一权威，不做量级推测。 实测易错点：雪深是「米」、降雪是「厘米」、风速是 km/h（项目内部统一换算为 m/s）、辐射是 MJ/m²。 这些换算全部写在常量与 meta 里，不散落在代码中。此前项目曾在雪深单位上判断失误，本版以自报值为准。

2.3 ⚠️ 必须写明的三条口径边界

① 负样本是「未确认」，不是「确认无灾」 训练/评价中作为负例的 1372 个月，其真实含义是「我们没有找到灾害记录」， 而不是「该月确无灾害」。数据集中单独保留 unlabeled 张量记录这一信息。 本报告所有指标都受此限制——它们衡量的是「与已记录事件的吻合度」。
② 正样本经过清洗：32 条非气象事件已剔除 原始 128 条正样本中，32 条不是气象事件：保险覆盖不足 17、地震 7、草场压力 4、牲畜疫病 2、疫苗接种 1。 把地震与疫苗当作「高原气象灾害」的正样本既让指标虚低，也经不起气象方向的追问。 清洗采取「加标注、不删记录」：原始记录保留，加 is_meteo 字段，下游按口径选择。
③ 气候数据与旧文件的口径差异已查明 与项目旧文件 climate_era5.json 逐日逐值比对（94103 个值）： 96.5% 完全一致，超阈值差异 99.3% 集中在 linzhi-bayi 一个县（该县不在事件标签集内）， 其余 5 县合计 20 处（占比 0.04%）。结论：25 县的标签集与气象数据同源可用。 另：API 返回的网格高程与项目 CSV 海拔最多相差 378 m （yushu-chengduo 3822 vs 4200），物理约束必须用 API 高程，因为温度来自同一网格。

3.2 双任务定义

任务输入目标类型指标
任务 A 同期识别[t−5, t] 的 26 县序列t 月该县有无气象灾害二分类AUC / AP / P / R / F1
任务 B 提前预测同上t+1..t+h（h=1,2,3）窗口内的最大灾情强度（0~4 连续量）回归R² / MAE / RMSE

任务 B 才是「预警」；也是时序模型相对树模型理论上有优势的地方（树模型没有序列记忆、不能外推时间趋势）。 灾情强度刻度来自标签 severity 文字档（低/中/高）映射，不是物理量纲。

3.3 损失函数

L_total = L_cls + L_reg + λ₁·L_lapse_rate + λ₂·L_snow_energy

L_cls  = Focal Loss(α, γ=2) + 难例挖掘 OHEM（保留 50% 困难负例，正例全部保留）
L_reg  = MSE（任务 B，有效掩码内）

L_lapse_rate : 对图上每条边 (i,j)
               residual = (T_i − T_j) + Γ·(h_i − h_j)/1000 ,  Γ = 6.5 °C/km
L_snow_energy: 单边（hinge）约束
               ① relu(ΔSD − 降雪量 − 容差)      没有降雪不应增雪
               ② relu(−ΔSD − 辐射可融雪量)      融雪不能超过辐射能上限
               辐射可融雪量 = rad(MJ/m²) ÷ 0.334(MJ/kg)     [雪密度按 0.1 折算]
物理项必须做尺度归一化（这是本报告里最实用的一条工程经验） 残差天然带量纲：气温差是「摄氏度平方」，积雪是「厘米平方」，量级远大于 Focal/MSE。 第一版直接用 λ=0.5，主任务 AUC 从 0.713 掉到 0.561（2022 年）——物理项把数据项压垮了。 修法：用观测的邻域温差、观测积雪变化的平均绝对值作为尺度把残差归一到 O(1)， 并把 λ 降到 0.05。修正后物理约束不再伤主任务，且在 2023/2024 两年提升了主任务指标。

3.4 ⚠️ 物理约束的诚实边界

这不是完整的积雪消融能量平衡 完整能量平衡需要：净短波 + 净长波 + 感热 + 潜热 + 地热 + 相变潜热。 现有数据只有日累计短波辐射，没有长波辐射、没有地表反照率、没有风廓线。 因此本文实现的是能量与物质守恒的单边软约束，不是能量闭合模型。
同理，L_lapse_rate 是26 个县点位之间的约束 （public_data/raw/dem/ 为空，没有 DEM 栅格），不是「相邻网格」约束。

4实验设计

  • 划分：滚动前向。训练 = 全部早于测试年的月份；测试 = 该年全年。样本单位 = (月, 县)。
  • 测试年：2022 / 2023 / 2024（三年各自独立出一份指标，看一致性而不是单年峰值）。
  • 随机种子：全部固定为 42，CPU 训练。
  • 基线：Logistic 回归、随机森林、XGBoost、CatBoost（传统）；LSTM、GRU、Transformer（时序深度）。
  • 消融：仅气象 → +遥感 → +空间图卷积 → +物理约束（= 完整 TP-STNet）。
  • 对比项：两阶段级联（低阈值粗筛 + 在筛出样本上重训精判模型）。
模型规模刻意取小，并说明理由 样本量 = 26 县 × 60 月 = 1560 格，气象类正样本 96 格（6.15%）；本机无 GPU（torch CPU 版）。 因此 d_model=48、时序编码器 1 层、图卷积 2 层，参数量 46,566。 深度用在结构上（跨模态 / 空间 / 物理约束），不是用在规模上——不假称「大模型」。 在这个样本量上堆参数量只会过拟合。

7.1 为什么达不到，三条根因

  1. 标签量太小，且负例性质不明。气象类正样本只有 96 格（占 6.15%），测试年正例仅十几格—— 一个样本的变动就是数个百分点。而 1372 个负例是「未确认」而非「确认无灾」， 模型学到的是「与已记录事件的吻合度」，不是真实的灾害概率。
  2. 提前预测的信息量本身不足。数据只有 2020-2024 五年、26 个县， 而灾害是小概率极端事件。任务 B 的 R² 为负，说明在这个尺度上「未来 1-3 月灾情强度」的可预测成分低于噪声。
  3. 物理侧数据不完整。只有日累计短波辐射，没有长波辐射、反照率、风廓线， 所以能量平衡只能做成单边软约束；没有 DEM 栅格，递减率只能做成点位约束。 这两项限制了物理先验能提供的增益上限。

7.2 下一步（按投入产出排序）

  1. 补长波辐射与地表反照率（ERA5 有对应变量）→ 把 L_snow_energy 从软约束升级为近似闭合，这是最有希望提指标的单项。
  2. 把评价口径从「月 × 县」改成「事件」（事件窗口 vs 随机窗口、命中率 @k），减少「未确认负例」对指标的污染。
  3. 扩充年份：ERA5 可回溯到 1979，把气象序列拉到 40 年，任务 B 的提前预测才有足够样本。
  4. λ 敏感性分析与更长回看窗口的扫描（当前 λ=0.05、回看 6 月是单点取值，未做网格搜索）。

python backend/deep_service.py

# 6) 起服务并访问算法接口
PORT=8100 python backend/server.py
#   GET /api/deep/status                  模型状态与训练配置
#   GET /api/deep/risk?month=2024-12      26 县风险评分
#   GET /api/deep/attention?month=2024-12 跨模态注意力在时间维的分布
#   GET /api/deep/attribution/{region_id} 通道遮挡归因 + 物理残差

模型归因用 通道遮挡（occlusion）而非 SHAP：把某一类输入置零，测风险下降幅度。 它的语义是「模型对该通道的依赖度」，可直接对上物理含义（温度 / 降水 / 积雪 / 辐射 / 风 / 湿度 / 遥感）， 比 SHAP 更经得起「这个数怎么算的」这一问。方法说明随接口一起返回，不做成好看的百分比。

9指标定义

指标含义读法
AUC排序能力0.5 = 随机
AP（PR-AUC）不平衡数据下的精确率-召回率综合基线 = 正例占比（0.062）
最优 F1 / P / R在测试集上扫阈值取 F1 最大乐观口径：实际部署拿不到这个阈值
P @ R≥90%要求不漏掉九成灾害时的精确率业务可解释口径
R @ P≥30%精确率压到三成时能不漏掉多少业务可解释口径
R²回归判定的解释比例为负表示不如直接预测均值
口径提醒 本报告所有「最优 F1 / P@R90 / R@P30」都由测试集上的阈值曲线给出，属乐观口径，不代表部署可达。 测试年正样本仅十几格，应看三年一致性而非单年峰值。
